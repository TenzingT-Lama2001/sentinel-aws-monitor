The two buckets, and why each is still there for a different reason

pipelinestack-support-ap-...eplicationbucket... (Sydney) — this is the support stack's replication bucket we just worked through. You correctly emptied it, then deleted the stack. It surviving is expected and correct — this bucket has no explicit RemovalPolicy set (remember, it silently falls through to the construct's default, which is RETAIN). Deleting the stack was never going to delete this bucket — RETAIN means "don't delete me even if my stack goes away." You did everything right; this is the bucket doing exactly what its (default) policy says.

pipelinestack-pipelineartifactsbucket... (Singapore) — this is a different bucket entirely — the pipeline's main artifact bucket (not the cross-region replication one), created by PipelineStack itself. If you've deleted PipelineStack, and this bucket is still showing up, that's the same RETAIN pattern applying here too — CDK Pipelines' main artifact bucket construct also doesn't set an explicit removal policy, so it also defaults to RETAIN.recursive
